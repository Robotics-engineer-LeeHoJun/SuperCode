## Summary
Deliver a beginner-friendly desktop hub that drives teams through the spec-kit golden path while orchestrating Codex, Gemini, and Claude CLI sessions, maintaining local-first privacy, and exposing dashboards for progress, agents, terminals, context, MCP, and checkpoints.

## Phase 0: Outline and Research
1. Document clarified routing presets, retention policy, automation presets, single-user scope, and GitHub Action decisions for CL-001 through CL-005.
2. Investigate recommended tech stack for a privacy-first desktop orchestrator, including GUI toolkit, PTY handling, and local database options.
3. Collect best practices for managing Codex, Gemini, and Claude sessions simultaneously, including login automation patterns and MCP integration.
4. Document compliance considerations for storing logs and checkpoints locally.
**Output**: `specs/001-supercode/research.md` capturing decisions, rationale, and alternatives.

## Phase 1: Design and Contracts
1. Model primary entities (Project State, CLI Session, Checkpoint, Role Prompt, Task Item) in `specs/001-supercode/data-model.md`, including attributes and relationships.
2. Define orchestration contracts: task routing rules, checklist APIs, login flow triggers, MCP registration interfaces (stored under `specs/001-supercode/contracts/`).
3. Draft quickstart journey outlining first-run flow, golden-path progression, orchestration execution, and recovery sequences in `specs/001-supercode/quickstart.md`.
4. Prepare acceptance checklists for role prompts and dashboards, referencing constitution principles.
5. Document the approach for syncing role prompt content with CLI context files (actual updates handled during implementation).
**Output**: `data-model.md`, `contracts/` artifacts, `quickstart.md`, and updated acceptance references.

## Phase 2: Task Planning Approach
- Convert design deliverables into actionable tasks grouped by research validation, UI workflow, orchestrator runtime, CLI adapters, state and checkpoint management, and UX polish.
- Order tasks to honor TDD and validation-first work: finalize research, solidify contracts, create failing tests and checklists, implement features, enable orchestration demos, then refine onboarding.
- Tag parallelizable items (for example role prompt authoring) and flag dependencies (for example CLI adapters require routing contracts).
- Ensure tasks cover documentation updates, sample presets, and log retention policies once clarified.

## Phase 3 and Beyond
- Execute tasks with CLI-specific branches, maintain checkpoints, and collect metrics for success criteria.
- Validate orchestration scenarios end-to-end, including login recovery and CLI failover.
